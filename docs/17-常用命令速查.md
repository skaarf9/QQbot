```powershell
# 启动 Koishi（排障用 --log-level 3）
cd D:\deepseek\QQbot\koishi-app
node node_modules\koishi\bin.js start --log-level 3
#   ★ 这条**本身没有任何自检**，而它恰恰是人和 agent 最常敲的那条（`npm start` 也是裸的）。
#     已经有实例在服务时再敲它：新实例抢不到 5140、只报一句 No open ports available（坑 6），
#     **却照样连上 NapCat 抢事件** → 群里每条命令两条回复（坑 57 / 坑 70）。
#   ★ 2026-10-04 起有兜底：配置里的 `onebot-singleton-guard` 会在**适配器建连之前**拒绝启动
#     （退出码 52，并打印收尾命令）。但它只是最后一道网 —— 正常启动请走下面那条启动器。

# ★★ 生产**只用这个**启动器（它带：按本地日期日志 + 启动前自检）
node tools\run-prod.cjs --log-level 3
#   日志 = tools\logs\prod-<本地日期 YYYY-MM-DD>.log
#   ★ 2026-10-06 修过两处：① 日期原来取的是 **UTC**（`toISOString()`），东八区要到早上
#     08:00 才换日，于是 prod-2026-10-05.log 里混着 10-06 的行；② 流是覆盖模式、开机后
#     也不再换文件，跑过半夜只会一直写老文件，同日重启还会把上一段抹掉。
#     现在按本地日期分文件、跨天自动换；同名旧日志先存成 prod-<日期>.prev-<HHMMSS>.log。

# 只看现状：5140 谁占着 / NapCat 上有几个客户端 / 有没有"孤儿实例"（坑 57）
node tools\run-prod.cjs --check

# 重启生产 = 一条命令（连正在服务的旧实例一起收掉再起）
#   先 job_kill 掉那个 dsh 后台 job（否则两个 job 混在一起看不出来），再：
node tools\run-prod.cjs --takeover --log-level 3

#   只收"丢了端口还在收 NapCat 事件"的孤儿（不碰健康实例，安全）：
node tools\run-prod.cjs --kill-orphans --log-level 3

# 安全停止 Koishi（★ 别用 CommandLine 匹配 'koishi'，会误杀 dsh 的 runner，见[部署与回滚](03-部署与回滚.md)里的警告）
#   ★★ 2026-10-03 第三次踩到：连 `-match 'run-prod'` 也不行 —— **正在执行这条命令的 dsh runner
#      命令行里原样带着 'run-prod' 这几个字**，`taskkill /T` 会把它一起带走，表现为工具报
#      「Windows Job runner exited with exit code 1 before proving its managed range empty」。
#      正解：先 `job_kill` 那个 dsh 后台 job，再用 `run-prod.cjs --check` 看还剩谁；
#      点名的 PID 用 `taskkill /PID <pid> /T /F` 精确收（★ 一定是进程树，见坑 6 / 坑 57）。
#   ★★ 2026-10-04 第四次踩到（这次是**测试脚本**杀的）：跑测试台时用
#      `Get-CimInstance Win32_Process | Where CommandLine -match 'bin\.js start'` 收实例 ——
#      **生产 CLI 的命令行里同样有 `bin.js start`**，于是生产被一起杀掉、停了 7 分钟（坑 70）。
#      收测试台/测试实例时，模式里一律要带 `-notmatch 'koishi-app'`；杀完立刻复核：
#      `node tools\run-prod.cjs --check`（生产该只剩 1 个客户端）+ `Get-NetTCPConnection -State Listen -LocalPort 5140`。
$c = Get-NetTCPConnection -State Listen -LocalPort 5140 -ErrorAction SilentlyContinue
if ($c) {
  $p = Get-CimInstance Win32_Process -Filter "ProcessId=$($c.OwningProcess)"
  Stop-Process -Id $p.ProcessId -Force                    # worker
  $par = Get-CimInstance Win32_Process -Filter "ProcessId=$($p.ParentProcessId)"
  if ($par.CommandLine -like '*bin.js start*') { Stop-Process -Id $par.ProcessId -Force }
}

# ★ 收尾自检：下面这条必须只剩 **1 个** PID，且它必须就是 5140 的 OwningProcess。
#   2 个 = 有孤儿，每条命令会被回答两次（坑 57）。
Get-NetTCPConnection -RemotePort 3001 | Select-Object State,LocalPort,OwningProcess
```

## 第十三轮：出站文本替换层（2026-10-05）

在**发送口**把模型输出里的指定文字换掉（需求原话：模型总是用 😏，它自己感觉不出来，
又不想改提示词）。**改发送口，不改提示词，也不改模型。**

| 敲什么 | 等级 | 干什么 |
|---|---|---|
| `/replacer`（= `/replacer.list`） | 1 | 看当前群生效的规则（id / 开关 / 原文 / 替换文本 / 命中次数） |
| `/replacer.add 😏 嘿嘿` | 3 | 新增一条（默认**只对本群**生效） |
| `/replacer.add 😏` | 3 | 省略替换文本 = 把 😏 直接**删掉** |
| `/replacer.add "你 好" 嗨` | 3 | 原文含空格用引号 |
| `/replacer.add -g 😏 嘿嘿` | **4** | `-g` = 全局（所有群与私聊）。**全局规则只有 4 级能改 / 删** |
| `/replacer.set 1 嘿嘿嘿` | 3 | 改 #1 的替换文本 |
| `/replacer.del 1`（别名 `remove`） | 3 | 删除 |
| `/replacer.on 1` / `/replacer.off 1` | 3 | 启用 / 停用（不删，随时开回来） |
| `/replacer.test 今天真开心😏` | 1 | **dry-run 预览**会变成什么，不改任何东西 |
| `/replacer.reload` | 3 | 从库里重新载入规则 |

三条语义（写进判据了，别凭感觉）：

1. **单趟最长匹配**：`😏` 与 `😏😏` 两条都在时，`😏😏` 命中后者；同长时群规则压过全局规则。
2. **替换结果不再扫第二遍**：`😏 → 😏呀` 只换一层，不会套娃。
3. **只动纯文本**：图片 / @ / 引用 / 表情包一律不碰。

规则落库（表 `chatluna_replacer_rule`），写完立刻重载、不用重启。
