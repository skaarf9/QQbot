# 技术选型（已定，勿反复）

> 属于 [QQ 机器人项目 —— 进度与交接](../进度与交接.md) 的分册。
> 旧编号（如「第八·十三节」）的去向见索引页的章节对照表。

这份是**结论**。评估过程与逐条对照见 `../nonebot-vs-koishi-13条需求调研.md` 与 `../astrbot-需求覆盖调研.md`。

### 主选：Koishi + ChatLuna

| 层 | 方案 |
|---|---|
| 协议端 | **NapCat**（小号 `2178517838`「星源」），正向 WebSocket |
| 框架 | **Koishi 4.18.11** |
| OneBot 适配器 | **`koishi-plugin-adapter-onebot` 6.9.4**（社区/官方组织新仓库版） |
| LLM/群聊行为 | **ChatLuna 生态**（阶段 2 才装） |

**选它的决定性理由：**

1. **生态最大**：Koishi registry ≈ 4695 条
2. **R13 最贴**：Koishi **内置 authority 0–4 等级制**，**每条指令、甚至单个选项**都能单独设等级；`@koishijs/plugin-admin` 的 `authorize` 命令可把等级下发给具体用户
3. **R7 最贴**：`chatluna-sticker` 用 **pHash 64 位去重 + 汉明距离**
4. **R2 最贴**：ChatLuna 预设目录 + `chatluna.use.preset` 命令切换
5. **权限贯穿到 agent 工具层**：ChatLuna 每个工具可单独设"所需最低 Koishi 权限等级"

### 被否方案（及原因）

| 方案 | 为什么没选 |
|---|---|
| **AstrBot + dsh** | 唯一有**现成 dsh 桥接**（`dsh-astrbot-ingress` 已发 npm）的生态，R8 官方模块最强；但权限不如 Koishi 精细，且"命令归框架、agent 归 dsh"是两套鉴权 |
| **MaiBot** | 群聊行为层**原生最强**（表情包三件套/引用含图片/reply_necessity 评分门控，6062★ 活跃）；但 R2/R11/R12 都要自写，**R12 根本做不到** |
| **全 dsh 原生** | dsh 有原生 OneBot 通道插件（`dsh-channel-qq` 等），R12 白拿；但通道插件是 2026-08/09 的年轻单作者仓库，且 dsh 生态与"群聊行为"耦合浅 |
| **NoneBot2** | 942 条里 `dsh`/`harness`/`deepseek` 命中 **0**；R4/R7/R9/R12 无现成件 |

> **唯一可能翻盘的变量**：若哪天认为 R12 用不上，就无脑上 Koishi；若认为 R12 的"真·闭环"最重要，则改用 AstrBot + dsh。
