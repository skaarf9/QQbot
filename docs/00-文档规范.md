# 00 —— 文档规范（体量、切分、校验）

> 属于 [QQ 机器人项目 —— 进度与交接](../进度与交接.md) 的分册。
> 旧编号（如「第八·十三节」）的去向见索引页的章节对照表。

**这份文档管"文档本身怎么长"。** 违反它的后果不是马上炸，而是**几轮之后没人再愿意读这些文档** ——
本项目的 `04-踩坑记录.md` 曾经一路涨到 2381 行 / 139 KB，索引页涨到 1304 行 / 151 KB，
每做完一轮都只加不减。这就是这份规矩要治的病。

> 加新功能前读 [硬约束](05-硬约束.md)；改**文档**前读这份。

---

## 1. 三条硬规矩

| # | 规矩 | 判据 |
|---|---|---|
| **D1** | **单文件不超过 800 行 / 80 KB** | 超了必须切段 —— `node tools/check-docs.cjs` 报 ERROR |
| **D2** | **叙事型文档按「类型 / 轮次 / 日期」切段** | 切完每份 ≤ 500 行；**编号、轮次号、段落内部顺序一律不变**；索引页要有「编号 → 文件」总表 |
| **D3** | **索引页只放"现在是什么状态"和"东西在哪"** | 索引页里不许出现"上一轮做了什么"的长记录（那是日志的事） |

### 阈值

| 档 | 行数 | 体积 | 动作 |
|---|---|---|---|
| **硬红线** | > 800 行 | > 80 KB | **必须切**；体检脚本 exit 1 |
| **警戒线** | > 500 行 | > 50 KB | 该切了；体检脚本给 WARN，`--strict` 下也 exit 1 |
| 单行 | > 400 字符 | — | WARN（表格行与代码围栏内不计） |

> 为什么是这两个数：800 行 ≈ 一屏 40 行的 20 屏，再长就没有"扫一遍"的可能；
> 80 KB 是 git diff / 编辑器高亮的实际舒适上限。500/50 是提前量，别踩到 800 才动手。

## 2. 切分维度（按内容性质选一种）

| 文档性质 | 例子 | 切分维度 | 结果长这样 |
|---|---|---|---|
| **编号累积型**（踩坑 / 问答 / 事件流） | `04-踩坑记录.md`（83 个「坑 N」） | **按类型（领域 / 阶段）** —— 同类一份，类内按编号升序 | `04-踩坑记录/01-环境与安装.md`、`02-市场生态与上游服务.md`…… **编号一个都不改** |
| **轮次累积型** | `24-指令页面化与图片库.md`（第一~四轮） | **按轮次** | `24-…/01-第一轮-….md`…… |
| **时间累积型** | `进度与交接.md` 顶部的逐轮交接 | **按日期** | `32-开发轮次日志/01-2026-10-02.md`…… |
| **主题混杂型** | `22-模型兜底队列与群聊上下文.md`（两个不相干主题） | **按主题** | `22-…/01-模型兜底队列.md` + `02-群聊上下文.md` |
| **参考速查型** | `17-常用命令速查.md` | **不切**（切了反而不好搜） | 保持单文件，但**必须在开头列出分区**，且 ≤ 800 行 |

### 为什么"编号累积型"要按类型、不按编号区间

按 `坑 1–20 / 21–40` 切，查的时候仍然要翻好几份 —— 因为**同一个领域的坑是散在全区间的**。
按**类型**切，才能做到"**我在做这件事，打开这一份，这一类踩过的坑一次看全**"：

- 切之前先列一张**类型表**（类型名 / 覆盖的编号 / 一句话说明），写进索引页；
- 一份只放一个类型；**类型内部仍按编号升序**，方便回查和 diff；
- 索引页同时保留**编号 → 类型**的总表，所以「见坑 57」照样能一步定位；
- **某个类型超过 80 KB / 800 行** → 在该类型内部按**子类型**再分一层
  （例：`06-消息出站与渲染/` → `01-图片与压缩.md` + `02-元素与排版.md`），并在类型表补一行。
  仍然不许为了"行数均匀"把同一个类型拆到两份去。

**切分的第一原则：编号、序号、日期一律不变。**
旧笔记里写的「见坑 57」「24 §13」「2026-10-03 那轮」必须还能查得到 ——
所以切完要在索引页放一张 **编号 → 文件** 的总表。

## 3. 目录与命名约定

```
docs/04-踩坑记录.md              ← 索引页（原名保留！历史链接零破坏）
docs/04-踩坑记录/                ← 同名子目录
    01-环境与安装.md
    02-市场生态与上游服务.md
    ...
```

- **`docs/NN-xxx.md` 被切时，这个文件必须留着当索引页** —— 仓库里有 100+ 处
  `[...](04-踩坑记录.md)`，改名或不留索引页会把它们全变成死链。
- 子目录名 = 索引页去掉 `.md` 的名字，**同名层级**（`docs/04-踩坑记录.md` ↔ `docs/04-踩坑记录/`）。
- 子文件编号用两位数字前缀（`01-`、`02-`…），后面跟**可读的类型名 / 段名**
  （`01-环境与安装.md`、`01-第一轮-指令页面化与图片库.md`）。
- 索引页里的链接写成 `04-踩坑记录/01-环境与安装.md`（相对索引页所在目录）。
- 子文件的链接写成 `../04-踩坑记录.md`（相对子文件所在目录）。

### 每份文件必备的结构

| 角色 | 必备 |
|---|---|
| 索引页（`docs/NN-xxx.md`） | 恰好 1 个 H1；`> 属于 [进度与交接](../进度与交接.md) 的分册。`；**切段表**（段名 + 覆盖范围）；正文末尾 `[← 回索引页](../进度与交接.md)` |
| 子段（`docs/NN-xxx/0N-….md`） | 恰好 1 个 H1（`# 父文档名 · 段名`）；一行说明"这属于哪份、怎么切的"；正文末尾回链**两处**：`[← 回 XX 索引](../NN-xxx.md)` 与 `[回总索引](../../进度与交接.md)` |
| 根文档（`进度与交接.md`、`接线与验证.md`） | 不受上面的"回索引页"约束（它们本身就是索引） |
| 任何文档 | 代码围栏 ` ``` ` 成对；相对链接目标必须存在 |

## 4. 新内容往哪儿写（最容易做错的一步）

> **核心：新的一轮/一个新坑 → 追加到"最新那一段"的末尾，或另起一段。绝不在中间插入、绝不重排。**

| 你要做的事 | 写到哪 |
|---|---|
| 踩了一个新坑（第 84 个） | ① 先看 `docs/04-踩坑记录.md` 的**类型表**，判断它属于哪一类；② 追加到那一份的**末尾**（同类内按坑号升序）；③ 在该类超过 **80 KB / 800 行**时，才在该类内部按**子类型**再分一层 |
| 做完一轮开发 | ① 新建 `docs/NN-本轮主题.md`（**首选**，一轮一文档）；② 或追加到该主题文档的**最后一段** |
| 生产实查 / 交接记录 | 写进**索引页的「当前状态」**，但同时把**上一轮那条搬去** `docs/32-开发轮次日志/<日期>.md` —— 索引页只留最近一轮 |
| 一条新命令 | 追加到 `docs/17-常用命令速查.md` 对应的**分区**里（先看开头的分区目录在哪） |
| 新增产出物 | 追加到 `docs/18-产出物清单.md` 的表里 |

**为什么一轮一文档最好**：`docs/19` ~ `docs/31` 就是这么长的 ——
一份文档讲一件事，天然不会变长，删起来也干净。
反过来 `24` 把四轮塞进一份，才需要切。

## 5. 校验

```powershell
cd D:\deepseek\QQbot

# 体检（只读，不写盘；有 ERROR 就 exit 1）
node tools\check-docs.cjs

# 顺带看最大的几份文档
node tools\check-docs.cjs --top 15

# 严格模式：把 WARN 也当 ERROR（准备提交前跑这个）
node tools\check-docs.cjs --strict

# 机器可读（给别的脚本用）
node tools\check-docs.cjs --json
```

体检**检什么**：

| 级别 | 项 |
|---|---|
| ERROR | 体量超硬红线（>800 行 / >80 KB） |
| ERROR | 死链（相对链接去掉锚点后目标不存在） |
| ERROR | `docs/` 下分册的 H1 数量 ≠ 1、或缺少「← 回」链接 |
| ERROR | 拆分一致性：索引页没链到子目录里某个文件 / 子文件没回链索引页 / 有子目录却没索引页 |
| ERROR | 踩坑编号重复、跳号，或没进索引页的坑号总表 |
| ERROR | 代码围栏不成对 |
| WARN | 体量过警戒线（>500 行 / >50 KB）、单行 >400 字符 |

> 体检脚本的阈值就写在 `tools/check-docs.cjs` 顶部的 `HARD_*` / `WARN_*` 常量里 —— 改规矩就改那里。
