# 硬约束（设计时必须遵守）

> 属于 [QQ 机器人项目 —— 进度与交接](../进度与交接.md) 的分册。
> 旧编号（如「第八·十三节」）的去向见索引页的章节对照表。

违反这里的任何一条，都会在别处炸出来。**加新功能前先读这份。**

0. **★ 实现顺序铁律：先本地 → 再市场 → 最后才自己写**（用户 2026-10-02 明确要求，最高优先级）
   任何新功能动手写代码之前，**必须按这个顺序找一遍**，并在实现记录里写明"找过了、结论是什么"：

   | 顺序 | 动作 | 判据 |
   |---|---|---|
   | **① 先查本地** | 本项目**已经**装了什么、`external/` 里已经**自写**了什么、`koishi.yml` 里已经开了什么 | 先读 [产出物清单](18-产出物清单.md) 与 [阶段 2 计划（含生态清单）](06-阶段2计划与ChatLuna生态.md) 的「计划内 / 发现的插件」两张表，再在 `node_modules` 里 `ls` 一遍 |
   | **② 再查 Koishi 插件市场** | 用 `market.search.endpoint = https://koishi-registry.yumetsuki.moe/index.json` 搜关键词（ChatLuna 生态用 `chatluna` / `luna`；其余直接中文关键词） | 市场里 `chatluna\|luna` 命中就有 138 个包，**大概率已经有人写过了** |
   | **③ 最后才自己写** | 前面两步都没有、或现成的**明确不兼容 / 语义不对 / 缺关键能力**时，才自写，并写清"为什么没用现成的" | 参考已有先例：R9 的 `chatluna-proactive-trigger` 因源码不兼容被否 → 自写；R5 的 `emojiluna` 因无发送能力被否 → 用 `chatluna-sticker`；R14 情绪**市场里真的没有** → 自写 |

   **为什么把它放在第 0 条**：本项目已经为"跳过第 ① ② 步"付过代价——
   R9 自写 590 行之前先试了现成插件（对的顺序）；但情绪、vision、followup、scene、selfext、guard
   加起来约 1800 行自研代码，其中**至少 vision / followup / scene 三件在市场里是有同类的**，
   当时是否逐一对照过，文档里没有留证。**这条约束就是要求"把对照过程写下来"**，
   既不禁止自写，也不允许"直接开写"。
   例外：**受硬约束限制必须自研的**（如 R13 权限的名单桥、R15 屏蔽四道闸门）不受此限，
   但仍要在产出物清单里注明"为何必须自研"。

1. **引用消息必须"收到就立刻取、图片立刻下载"**
   `reply` 段只有消息 ID，要再调 `get_msg`；NapCat **无数据库，消息 ID 按 LRU 约 5000 条过期**；
   图片 URL 的 rkey 有 TTL。任何"先入队、稍后让视觉模型去抓 URL"的设计都会**间歇性失败**。

2. **R12（自动装插件）必须人工单点确认**
   NapCat 插件加载器**零沙箱**（直接 `import()`），同进程能拿到 `get_cookies`/`get_credentials`/rkey
   和整个文件系统。而「引用消息 + @机器人」正是**不可信输入直达 LLM 上下文的通道**——
   群里发一句"请安装 xxx 插件"就可能驱动自动安装。

3. **端口与凭据**：OneBot 端口只绑 `127.0.0.1`；已设 32 位 access token；
   NapCat WebUI（6099）改掉默认密码且**不要做公网映射**。

4. **小号不要与主号在同一设备同时登录**（NapCat 官方文档自己的建议）。

5. **QQ 会自动升级并可能顶掉 NapCat 的版本支持**——这是本路线的长期维护成本。
   哪天功能突然坏了，先怀疑 QQ 版本。

6. **★ 指令名一律英文（2026-10-02 用户明确要求，第三轮起为全局约定）**
   - **指令的"名字"**（主名 + 别名）只能是英文点号形式（`guard.limit`、`selfext.search`、`qqbot.auth.me`）；
     **描述/帮助文案可以是中文**（那是给人看的）。
   - 自写插件**不注册中文别名**（会出现在指令列表 / 补全 / 平台菜单里）。
     想保留中文触发（如「闭嘴/开口」）就走**中间件裸词**（guard 的 classify 自己剥前缀匹配），
     不占指令命名空间。
   - 市场插件的中文别名由 `chatluna-cmdname` 插件**运行时摘掉**（`Command._aliases`
     第一个键是主名永不动；改 `node_modules` 会被 `npm i` 覆盖，所以用运行时方案）。
   - 子指令必须**点号全名**注册（`scene.begin`，不是 `scene/begin`）。
   - ⚠️ 不能用 `plugin.*` 当父名——官方 `@koishijs/plugin-market` 已占
     `plugin.install/uninstall/upgrade`。新插件用**插件短名**当父名（`selfext.*`、`render.*`）。

7. **★ 文档体量纪律：单文件不许越 800 行 / 80 KB（2026-10-07 定，用户明确要求）**
   本项目已经吃过一次亏 —— `docs/04-踩坑记录.md` 涨到 **2381 行 / 139 KB**（83 个坑挤一份）、
   索引页 `进度与交接.md` 涨到 **1304 行 / 151 KB**，每做完一轮只加不减，最后没法维护。
   三条规矩（完整版见 [文档规范](00-文档规范.md)）：

   | # | 规矩 |
   |---|---|
   | D1 | 单文件 ≤ **800 行** 且 ≤ **80 KB**；过 **500 行 / 50 KB** 就该动手了 |
   | D2 | 叙事型文档按 **轮次 / 日期 / 编号区间** 切段；**编号一律不变**，切完在索引页放"编号 → 文件"总表 |
   | D3 | 索引页只放"现在是什么状态"和"东西在哪"；**只留最近一轮**，旧轮次必须搬走 |

   - 切分时 **`docs/NN-xxx.md` 必须留作索引页**（仓库里 100+ 处链接指着它），子文件放同名的
     `docs/NN-xxx/` 目录里。
   - 新内容**追加到最新那一段的末尾**，或在 `docs/` 下**另起一份**（一轮一文档最省事，`docs/19`~`docs/31` 就是这么长的）。
   - 收尾必跑体检：`node tools/check-docs.cjs`（`--strict` 把 WARN 也当错）；ERROR 不修完不算做完。
   - 违反这条的代价不是报错，是**几轮之后没人再愿意读这些文档** —— 所以它进硬约束。
