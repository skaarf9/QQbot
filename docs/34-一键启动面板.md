# 34 —— 一键启动面板（Koishi + NapCat 控制台）

> 属于 [QQ 机器人项目 —— 进度与交接](../进度与交接.md) 的分册。

**这一轮要的是什么（用户原话拆出来的四条）**：

1. 一键启动 Koishi 和 NapCat 的界面（Web UI 或 Windows 窗口都行）；
2. NapCat 登录/掉登录时自己生成的**二维码**要能在这个界面里看到；
3. 两边的**日志**能看，带点格式化和样式，美观一点；
4. 两个自带的 WebUI 要有跳转链接（点名字就能开），**NapCat 那页要填 token，最好能跳过**。

落地产物：`tools/panel/`（`server.cjs` + `public/` + `tests/`）+ 仓库根的 `启动面板.cmd`
与 `启动NapCat.cmd`（后者是"面板起不来 NapCat 时"的手动入口，见第七节第 5 条）。
用法与排障写在 [`tools/panel/README.md`](../tools/panel/README.md)（那份是操作手册，本份讲决策与取证）。

---

## 一、为什么是"本地 Web UI"而不是 Windows 窗口

| 方案 | 代价 | 结论 |
|---|---|---|
| Electron / Tauri 窗口 | 多一个几百 MB 的运行时依赖，打包/签名都要管 | 否 |
| PowerShell + WinForms | 零依赖，但**日志滚动区、二维码图、可点击链接**都要手搓，样式基本没法看 | 否 |
| **本地 HTTP 服务 + 浏览器页面** | 零依赖（只用 node 内置模块），样式随便写，日志流用 SSE | **采用** |

浏览器页面挂在 `127.0.0.1:5151`，`启动面板.cmd` 负责"起服务 + 开浏览器"。
关掉那个命令行窗口只是停掉面板本身，Koishi / NapCat 不受影响（这点在 UI 上也写了）。

## 二、四条需求分别是怎么落地的（每条的取证）

### 1. 一键启停

- **Koishi** 走 `koishi-app/tools/run-prod.cjs`，不自己拼 `koishi start`：
  这个脚本已经处理了三件我们已经踩过的事 —— 按**本地日期**落盘日志（跨天自动换文件）、
  启动前查 5140 占用、以及**孤儿实例检测**（坑 57：端口空着也可能有实例还在收 NapCat 广播）。
  面板的「启动」默认带 `--takeover`，复选框可关。
- **NapCat** 走 `tools/start-napcat-shell.bat`（它会自提权），面板额外做两件事：
  ① 生成 `.runtime/panel/napcat-launch.cmd` 把输出重定向到我们能 tail 的文件里；
  ② 提权拉起这个包装器。**注入 QQ.exe 就一定需要管理员**，面板能做的是把这一次 consent
  收拢到"一次"：**推荐让面板自己带管理员跑**（`启动面板.cmd` 现在会先给自己要一次 UAC），
  之后每次点「启动 NapCat」都是直接创建进程、**不再有 UAC**。
  面板没提权时，第一次尝试仍走面板侧的 `Start-Process -Verb RunAs`（本机实测弹不出提示，见第七节 5），
  真正的退路是卡片上的 **「控制台启动」**：开一个真实控制台窗口跑同一个 bat，
  由**脚本自己**去要 UAC —— 和用户双击脚本完全同一条链。

### 2. 二维码

**取证**：`napcat.mjs` 里收到二维码时 `writeFile(join(cachePath, 'qrcode.png'), Buffer.from(base64))`
（`onQRCodeGetPicture` 分支）。所以：

- 面板**盯 `NapCat.Shell/cache/qrcode.png` 的 mtime**，变了就给 `<img>` 换 URL（带 `v=<mtime>`）；
- 不需要连 QQ、不需要 WebUI 权限就能拿到图 —— 这是选它而不是走 API 的原因；
- **坑**：登录成功后 NapCat 不会删这张图，于是"文件存在"≠"现在要扫码"。所以面板只在
  **没登录 且（NapCat 在跑 或 图 <3 分钟）** 时才把它当当前二维码展示，否则显示灰框写明
  "有一张 N 分钟前的旧图"。旁边同时显示登录阶段（等待扫码 / 已扫码待确认 / 已登录 / 掉线重连）。

一句话：**图看文件，状态看 API，两者互相印证**。

### 3. 日志

三条来源、两种机制：

| 来源 | 机制 |
|---|---|
| Koishi 实时 | 面板自己 spawn 的 `run-prod.cjs` 的 stdout/stderr（**不设 `FORCE_COLOR`**，见下） |
| Koishi 历史 | `koishi-app/tools/logs/prod-<日期>.log`（`run-prod.cjs` 的 tee） |
| NapCat | `NapCat.Shell/logs/<日期>.log`（winston）+ 面板重定向出来的 `.runtime/panel/napcat-console.log` |

- 服务端做**增量 tail**（记 offset、处理截断/轮转、UTF-8 跨块边界），解析出 `lvl` 与 `tags`，
  通过 SSE 推给页面；页面按级别上色、把时间戳抽到独立栏、支持"空格分隔=全部命中"的关键字过滤、
  级别筛选、自动滚动、换行开关、导出。
- **★ 不要给 Koishi 子进程设 `FORCE_COLOR`**：`run-prod.cjs` 会把子进程输出同时写进日志文件，
  带上 ANSI 转义就污染了 `docs/17` 那套 `Select-String prod-<日期>.log` 的排障流程
  （实测：正常运行的日志文件是纯文本）。级别是从 `[I]/[W]/[E]` 这个纯文本标记认的。
- 级别识别顺序：winston 的 `[info]` → Koishi 的 `[I]` → 关键字兜底；**认出后把标记本身从正文摘掉**
  （左侧已经有级别列了，正文再来一个 `[I]` 只是噪音）。
- NapCat 会把**终端二维码**打进日志（`qrcode-terminal` 的块字符）。面板会认出这种行、压紧行高、
  黑底白块、把时间戳栏藏掉 —— 不掉这一手的话那个图案会被行高和时间戳戳散。

### 4. 免 token 跳转

**取证**：NapCat WebUI 的前端登录分包（`static/assets/web_login-*.js`）里有
`new URLSearchParams(window.location.search).get("token")`，拿到就自动 `loginWithToken`；
路由 basename 是 `/webui/`。所以链接写成：

```
http://127.0.0.1:6099/webui/?token=<config/webui.json 里的 token>
```

点开即登录，token 从 `webui.json` 现读（不落库、不硬编码）。另有「复制 token」备用。

## 三、面板自己怎么读 NapCat 的登录状态

不去改 NapCat 的任何配置，按它的 WebUI API 走一遍（**取证都在 `napcat.mjs` 里**）：

1. `/api/auth/login` 的 body 是 `{hash}`，而 `hash = sha256(token + ".napcat")`（`generatePasswordHash`）；
2. 返回的 `Credential`（base64(签名 JSON)）在 1 小时内有效；
3. 之后的请求要么带 `Authorization: Bearer <Credential>`，要么带查询参数
   `?webui_token=<Credential>`（鉴权中间件两种都收）；
4. 用 `/api/QQLogin/CheckLoginStatus` 拿 `isLogin / loginPhase / qrcodeurl / loginError`，
   `/api/QQLogin/RefreshQRcode` 刷新二维码，`/api/QQLogin/RestartNapCat` 重新登录。

面板把 Credential 缓存在内存（50 分钟），过期自动重登。2FA 打开时会明确报"面板拿不到 Credential"，
不装作能工作。

## 四、两个安全边界（这东西是个能启停进程的本地服务）

1. **只 bind `127.0.0.1`**，不监听外网；
2. **所有 `/api/*` 要面板自己的随机 token**（随页面下发；别的网页读不到我们的 HTML，
   所以能挡住"恶意网页打本地端口"这类 CSRF），`/api/ping` 例外 —— 它是"这个端口上是不是本面板"
   的探针，只回应用名和版本，用来实现"重复启动只开一个浏览器标签"；
3. **`Host`/`Origin` 必须是本机面板端口**（挡 DNS rebinding）；
4. `<img>` 带不了请求头，所以二维码图片接口额外允许 query 里的 token；
5. 能开目录的 `/api/open-folder` 只认白名单（两个日志目录 + 仓库根 + 面板运行时目录）。

## 六、停 NapCat 为什么不是简单的"全杀 QQ.exe"

NapCat 注入在 QQ.exe 里，没有独立进程可杀 —— 仓库里原本的答案是
`NapCat.Shell/KillQQ.bat`（`taskkill /f /im QQ.exe`）。如果主号 QQ 正好开着，那一下会连主号一起杀。

面板记着"NapCat 是什么时候被本面板拉起来的"（`.runtime/panel/state.json`，面板重启也不丢），
停的时候按 `Win32_Process.CreationDate` **只收启动时间在那之后的 QQ.exe**，
于是主号 QQ 不受影响。只有"面板不知道是谁起的 NapCat"时才退回全杀，而且必须由前端显式带
`force: true` —— 那时二次确认框里会写明"会连主号一起杀"。

## 七、实施中真实踩到的坑（写下来省得下次再犯）

1. **`启动面板.cmd` 第一版是废的**：我用平常的方式写文件（UTF-8 + LF），于是 cmd.exe
   一边按 OEM 代码页把中文回显解成乱码、一边把 LF 当行内字符，整个脚本碎成一句，
   症状是 `'xxx' is not recognized as an internal or external command` 刷屏。
   **规矩：`.bat` 只写 ASCII、只用 CRLF**（仓库里 `tools/start-napcat-shell.bat` 的注释就是这么写的）。
   教训：**入口脚本本身也要真跑一遍** —— 我先把服务端 10 条接口判据跑通了，却差点漏掉"双击那一层"。
2. **"谁在跑"别用错端口**：第一版 `koishiRunning()` 同时看 5140 和 3001，
   于是只启动 NapCat 时面板会报"Koishi 在跑"。3001 是 NapCat 的 WS 服务端端口
   （而且测试台的伪 OneBot 也听它）。现在 Koishi 只看 5140，NapCat 以 WebUI 6099 为主。
3. **停 NapCat 不能只有"全杀"这一条路**（见上一节），否则主号 QQ 会被误伤。
4. **日志解析要拿原始字节定格式**，不能凭印象：抓下来的 Koishi 输出是
   `YYYY-MM-DD HH:MM:SS [I] scope msg`（管道下没有颜色），而 NapCat 是 winston 的
   `MM-DD HH:mm:ss [level] 昵称 | msg`。另外**认出级别后要把级别标记从正文摘掉**，
   否则左侧级别列 + 正文 `[I]` 会有两份。
5. **★ 提权是这个面板最大的坑，分两层。**
   **(a) 会无限期挂**（用户实测报回的第一件事）：`Start-Process -Verb RunAs` 会一直等 UAC 的应答，
   而 UAC 提示是弹在**安全桌面**上的（屏幕变暗）。没人应答 → 那个 powershell 永不返回，
   而当时的代码是裸 `await`，于是面板**永远停在「启动中…」**；同时 NapCat 的"自动"日志源落到了
   一份**三天前**的 `napcat-framework-console.log` 上（只有两行 `framework launch`），
   用户看到的现象就是"点了启动，NapCat 什么都没打印，也没起来"。
   修法：① 提权加超时（现在是 60 秒，`PANEL_ELEVATE_TIMEOUT_MS` 可调），超时收掉提权进程并明确报错；
   ② 失败/超时时清掉 `startedAt`（否则界面一直"启动中"，而且 `managed=true` 会让下一次停止
   按时间窗口去收 QQ.exe，可能误伤）③ 加「复位」按钮兜底；④ 日志来源那行写"文件最后更新 X 前"，
   旧文件直接标 **⚠ 这不是实时输出**。
   **(b) 非管理员面板里那条提权在本机根本弹不出提示**（用户第二轮实测的原话：
   "我自己点这些脚本都会显示提权，但网页里点启动却不会"）。取证链：面板
   `app.elevated = false`（说明走的正是这条路）、`lastStartError = "UAC 提权窗口等了 100 秒没有回应"`、
   `.runtime/panel/napcat-console.log` **压根没生成**（包装器一行都没跑过）。
   改法（**绕开它，而不是继续调它**）：① 目标从 `.cmd` 换成真 exe —— 命令改成
   `Start-Process -FilePath 'cmd.exe' -ArgumentList '/c','<包装器>' -Verb RunAs`，
   逐字对齐 `tools/start-napcat-shell.bat` 里那条被用户验证过无数次的写法；
   ② **`启动面板.cmd` 自己先提权**（一次 UAC / 每次开面板），面板是管理员后启动 NapCat
   走直接 `CreateProcess`，**彻底不碰 UAC**；③ 新增「控制台启动」按钮：开真实控制台跑同一个 bat，
   让脚本自己去要 UAC（和双击脚本同一条链）；④ 面板侧那条提权保留作兜底。
   **引号的实测结论**（`.scratch/gen-quote-probe.cjs`，四种写法各真跑一遍，只去掉 `-Verb RunAs`）：
   路径无空格时**裸路径 / `\"…\"` / `"…"` / `[char]34` 全都能跑**；路径带空格时**四种全败** ——
   因为路径被展开进 `-Command "…"` 那个字符串，powershell 按空格把它切开了。
   所以别在路径上堆引号，`启动面板.cmd` 里加了"路径含空格就报错并让你用右键提权"的拦截。
   教训：**这条链上的失败全是静默的**（参数错、提示没弹、应答被忽略，现象都是"点了没反应"），
   所以要么让它别经过 UAC（自提权面板），要么让它经过用户验证过的同一条路（控制台启动）。
6. **★ `启动面板.cmd` 里 `%ROOT%` 的结尾反斜杠不能"顺手规范化"。**
   我加了一行 `for %%I in ("%ROOT%.") do set "ROOT=%%~fI"`（很常见的去尾斜杠写法），
   反斜杠没了，于是后面 `"%ROOT%tools\panel\server.cjs"` 拼成了 `D:\deepseek\QQbottools\panel\server.cjs`
   （少了一个分隔符），启动器一跑就 `[x] tools\panel\server.cjs not found`。
   注意第一版**没有**这一行、是好的（v1 用 `set "ROOT=%~dp0"` 直接留下尾斜杠）。
   教训：**入口脚本每改一次都要真的跑一遍**，语法/静态检查全看不出这类错。
7. **"换 Framework 变体就能绕开主号 QQ 冲突"是错的**（我一开始的假设，已经写进代码和 UI 又改掉）：
   取证 —— `NapCat.Framework\napiLoader.bat` 同样从注册表读 QQ 路径，`napimain.exe` 里的字符串是
   `launcher.exe <QQ> [DLL]`。**两个变体都是"启动并注入你已装的那个 QQ"**，所以都要管理员、
   都会撞 QQNT 单实例。变体只影响注入方式（Shell = `NapCatWinBootMain.exe` + JS 加载；
   Framework = `napimain.exe` + `napiloader.dll` 原生加载）与对不同 QQ 版本的兼容性。
   绕开单实例只有两条路：先退出主号 QQ，或另装一份 QQ 专供 NapCat
   （两个 bat 都写死了注册表路径，面板目前**不支持指定 QQ 路径**，要做就得让启动器接受显式路径）。
   教训：**别从目录名推断行为**（"Framework"听着像"自带框架"），去读它的 bat 和 exe 里的字符串。
8. **前端把 `**粗体**` 当纯文本显示了。** 对话框和提示行都用 `textContent`，于是页面上直接出现
   `**弹不出提示**` 这种星号（文案是给"人读"写的，写的人以为会渲染）。
   现在统一走 `richText()`：先转义 HTML，再把 `**x**` 换成 `<strong>`（只放行这一种标记，防注入）。

## 八、留给以后的

- 面板目前**不持久化 Koishi 的运行状态**（面板重启后「运行时长」清零，进程仍在跑）；要不要存，
  等真觉得别扭再说。

  面板没有替用户改这个配置 —— 需要更细的 NapCat 日志时，自己开，或者看面板的控制台捕获。
