## 一、`/vision.this`：引用一张图，看系统把它认成了什么（只读）

```
引用一张图 + @bot + /look          ← 别名，等价于 /vision.this
/vision.this -f                    ← 这张还没被看过时，现场认一次（★ 这一条会调用视觉模型）
/vision.this --hash                ← 只看 hash / pHash 与表情包库是否在库
```

输出（默认**不调用任何模型**）：

```
━━━ 引用的图 ━━━
sha256 3f9a2c1b… ｜ pHash 8a3c1d2e3f4a5b6c ｜ 77940 字节 ｜ image/jpeg
缓存：命中 sha256｜版本 v2｜描述模型 cc/q.vision｜解析于 10-04 02:31
自我标记：★ [自己] —— 模型认为画的就是 bot 自己
描述：[自己] 大肥鱼穿女仆装托腮疑惑，旁边写着"!?"和蓝色小鲸鱼。
修正痕迹：无（还是视觉模型的原始输出）
表情包库：★ 在库（027fcd8392b6929e｜用过 3 次）
  库内描述：蓝发女仆装Q版角色睁大眼睛一脸困惑，旁边配着"!!?"惊叹气泡
  库内标签：自己 / 无语
想改描述：/vision.correct 3f9a2c1b <新的描述>
```

### 为什么默认不调模型

要测的正是"**上一轮对话里模型到底看到了哪句话**"。如果这条指令自己顺手重解析一次，
就把要观察的对象改掉了 —— 所以默认纯读库，`-f` 才是显式的一次 AI 调用，
`--hash` 连描述都不看（只看它在不在库里）。

### 为此加的库列（`chatluna_image_cache`）

| 列 | 作用 |
| --- | --- |
| `selfFlag` | 描述带 `[自己]` / `[可能自己]` 时的结论（yes/maybe/no），可以直接 SQL 统计 |
| `correctedFrom` | 改前的原描述（"模型原来认成了什么"的唯一痕迹） |
| `correctedBy` | `tool:vision_correct` / `command:vision.correct` —— 分清是模型自己改的还是人改的 |
| `correctedAt` | 改的时间 |

四列都是 nullable 的新增列，Koishi 启动时自动 `ALTER TABLE ADD COLUMN`，旧行不受影响。
**没有这四列时，"这条描述是模型原始输出还是后来改过"根本看不出来**，也就没法验"自我修改"这条链。

## 二、人设卡片：一份身份，多个阶段共用

### 2.1 问题

「我是谁」原来只写在对话预设里。可同一个角色不止一个模型在演：

| 阶段 | 原来的状况 |
| --- | --- |
| 视觉模型 | **完全不知道角色的存在**。bot 自己的形象被描述成"蓝色小女孩""蓝发猫耳女仆"（耳朵都认错了），对话模型看到这句认不出是自己 |
| 记忆总结模型 | 摘要里的 bot 发言标成「你（大肥鱼）」—— 对**它**来说"你"毫无所指，摘要正文里因此常出现无主的"你" |
| 表情包打标/判定 | 提示词里没有任何身份概念（打标："蓝发女仆装Q版角色"，实际就是她自己） |
| 长期记忆抽取 | 见 §2.4：它连 bot 的发言都收不到 |

### 2.2 做法

新增 `data/persona/self.yml` —— **身份事实的唯一来源**（名字 / 别名 / 一句话 / 形象 / 判定口径 /
反向口径 / 自称 / 口头禅 / 参考形象图），新增自研插件 `chatluna-persona` 提供：

```
ctx.chatluna_persona.block('dialogue' | 'vision' | 'summary' | 'memory' | 'sticker' | 'proactive')
{persona()}          ← 预设里用（等价于 block('dialogue')）
/persona.show        ← 看卡片 + 各阶段实际收到的那段话（authority 3）
/persona.reload      ← 改完 self.yml 立刻生效（不用重启）
/persona.image       ← 把参考形象图发出来看一眼
```

改完 5 秒内自动重载（mtime 检查），也可以 `/persona.reload`。

### 2.3 ★ 「你」还是「我」—— 按消费方分，不是二选一

这是本轮第 4 条的答案，写在 `chatluna-persona/lib/index.js` 的 `block()` 注释里：

| 消费方 | 人称 | 为什么 |
| --- | --- | --- |
| **对话模型** | 第二人称「你」 | 它**就是**这个角色。"你是大肥鱼"才是它自己的身份；而且系统提示词的说话者是主人/平台，第二人称才是自然语域。现有预设整篇都是「你」，混用会让它自述时精神分裂（实测过会冒"我是大肥鱼，你是一个 AI"这种串味输出） |
| **视觉 / 记忆 / 表情 / 把关**（工具模型） | **第三人称角色名** | 对这些模型来说，"我"是模型自己、"你"是调用它的人 —— 两个都不是大肥鱼。写成"你是大肥鱼"它们会把自己的身份和角色搅在一起（视觉模型开始自称鲸鱼娘），写成"我是大肥鱼"更糟。**描述一个不在场的第三方**才是它们该干的活 |

所以：**卡片文件里的事实一律中性第三人称写**，由 `block(kind)` 翻译成各阶段的口吻。
新增一个阶段时只加一个 `case`，不要去改卡片。

配套改了 `chatluna-episode`：`renderLines(rows, {view})`
—— `view:'self'`（默认）渲染成「你（大肥鱼）」给对话模型；
`view:'third'` 渲染成「大肥鱼（机器人）」给总结模型（滚动总结的 prompt 已切过去）。
bot 的显示名也统一问卡片（`botDisplayName(ctx)`），不再在三处硬编码 "大肥鱼"。

### 2.4 记忆：哪些是"自己说的"

- **短期情景记忆（chatluna-episode）**：bot 的发言本来就有 `isBot` 列，但渲染给总结模型时用的
  是"你"，现在改成第三人称并在总结提示词里加了一段"哪一行是机器人说的"。✅ 本轮修好
- **长期记忆（chatluna-long-memory，npm 1.4.0）**：**它压根收不到 bot 的发言**。
  `lib/index.mjs:166-168` 把 `getType() === 'ai'` 的消息整条丢弃，格式化只有 `User:` / `Assistant:`
  两个硬编码标签，`name`（昵称）字段全程没用，记忆条目 `EnhancedMemory` 也没有说话人字段
  （`lib/types.d.ts:16-23`）。所以那边不存在"认错说话人"的问题 —— 但也意味着
  **bot 说过的话永远不会进长期记忆**（目前看是合理的：长期记忆是记群友的）。
  唯一的非 patch 改造口是未公开的 `preset.config.longMemoryExtractPrompt`（`lib/index.mjs:180`，
  必须自带 `{user_input}` 占位符，ChatLuna 核心从未定义过这个字段，UI 里配不到）。
  **本轮刻意没有动它** —— 要覆盖就得把 121 行英文提示词整段抄进配置，维护成本大于收益。

### 2.6 视觉自我识别的三种做法（第 2 条里"要不要配图"的评估）

配置：`chatluna-vision.selfCompare = off | text | image | auto`
（`selfAware` 总开关；参考形象图默认取 bot 的 QQ 头像，缓存到 `data/persona/cache/`）

| 模式 | 做法 | 成本 |
| --- | --- | --- |
| `off` | 不注入身份（旧行为） | 0 |
| `text` | 描述提示词前面加一段"这个角色长什么样/什么算她/什么不算她"，要求描述开头打 `[自己]` / `[可能自己]` 标记 | 每个请求 +约 250 字 |
| `image` | 在**待识别图之后**再附一张参考形象图 + 一句"这张只用于比对，不要描述它" | 每张图多传约 30~60KB 的 base64（压缩后） |
| `auto` | 先纯文字；模型自己标了 `[可能自己]` 才带参考图重认一次 | 只有拿不准的图才付第二笔 |

**实测（rig 61，8 张图：3 张确定是自己 + 1 张存疑 + 4 张不是，含两张难负例）**：

| 模式 | 自己 3 张 | 存疑 1 张 | 负例 4 张 | 描述质量 |
| --- | --- | --- | --- | --- |
| `off` | **0/3** 带标记 | 0 | 0 误标 | 「蓝发女仆装少女**头顶有角**」「蓝发**兽耳**女仆装角色」—— 鲸鱼鳍耳被认成角/兽耳 |
| `text` | **3/3** | 标成 `[自己]` | **0 误标** | 「蓝色长发、**鲸鱼鳍耳**的鲸鱼娘穿黑蓝女仆装」「旁边写着"!?"和蓝色小鲸鱼」 |
| `image` | **3/3** | 标成 `[自己]` | **0 误标** | 同上，略更细：「围裙印小鲸鱼，表情懵，旁边写着"!!?"」 |

三种模式的原始输出都在 `.scratch/rig61-off.log` / `rig61-text.log` / `rig61-image.log`，
用 `node .scratch/check-61.cjs <日志> <模式>` 复算。

难负例的关键两条：**蓝发兔耳少女**（颜色对、耳朵不对）和**浅蓝发校服少女**（颜色对、元素全不对），
`text`/`image` 模式下都没被误认成自己（`off` 模式反而把兔耳认成"粉色大耳朵"、把鲸鱼鳍耳认成"角"）——
判断依据正是卡片里那句"鲸鱼元素（鳍状耳 / 鲸鱼图标 / 鱼尾 / 小鱼饰品）"。

**结论（回答"只使用文字就够了吗"）**：
- **够用**。默认 `text`：零额外图片传输，8/8 正确，误判靠"判定口径 + 反向口径"两句话压住。
- 但**必须写反向口径**（"真实鲸鱼照片、没有鲸鱼元素的其他蓝发角色都不算她"）。
  只写正向特征时，模型会把"蓝色系 + 二次元少女"一律认成自己 —— 这是这类判定最常见的错法。
- `image` 模式留给"认错了、想让它更准"的场合：`/vision.this` 看到误判就临时切 `image` 验一次，
  或者干脆用 `vision_correct` 把描述改对（改完永久生效，比每次多传一张图便宜得多）。
- 因此**不需要每次都发两张图**：参考图是**插件自己附的**（用户只发一张），而且只在 `image` 模式下才附。

### 2.7 表情包链路

- `sticker-admin` 的打标提示词前面也加了卡片（`block('sticker')`）：画的是她 → 描述里写
  "大肥鱼（自己的形象）"并加标签「自己」，于是 `sticker_search` 的结果里能直接看出来。

## 三、作息表：让 bot 有自己的日子

新增自研插件 `chatluna-routine`（配置块 `chatluna-routine:rtn001`）。

### 3.1 时段与生活事件

```yaml
blocks:
  - id: sleep    # 23:30~08:00   quiet: true
    enterText: 我先去睡了……别吵我。
    exitText: 我睡醒了。
  - id: lunch    # 12:00~12:40
    enterText: 我先去吃饭啦！这个你测一下~
    exitText: 吃完了，回来啦。
  - id: dinner   # 18:30~19:10
    enterText: 到饭点了，我先去吃饭。
    exitText: 吃完了。
```

- 切换的那一刻把 enter/exit 文本**写进情景记忆**（chatluna-episode 的新接口
  `broadcastBotLine` → 所有群会话各写一条 `isBot` 行）：
  于是 `{episode()}` 里会出现「[12:03] 你（大肥鱼）: 我先去吃饭啦！这个你测一下~」，
  半小时后回来接着聊，它记得自己去干嘛了。
- **默认不真的发到群里**（`announce: false`）。想让它真说话就开 `announce` 并配 `announceGroups`。
- `jitterMinutes`：每天前后浮动 ±N 分钟，**同一天内固定**（按日期+时段 id 做散列），
  像真人一样不卡点，也不会每次心跳都漂。
- **重启不补台词**；宕机错过的切换超过 `catchUpMinutes`（默认 20 分钟）只更新状态、不写记忆 ——
  否则重启/宕机后会"补播"出穿越的台词。

### 3.2 `{routine()}` 变量（已加进预设的【你在过什么日子】）

```
【你现在的时间表】现在是 10-04 03:12
★ 你正在【睡觉】（23:41 上床，睡到 08:07，已经睡了 3 小时 31 分）。
正常这个点你根本不该出声 —— 如果现在有人找你，说明你是**被硬叫醒的**。
按你的性格反应就行（迷糊、不爽、先抱怨一句再干活、或者干脆怼回去），别装作没事；
真被吵烦了就把心情也改掉（emotion_set），别只在嘴上凶。但也别真的骂人。
今天的安排：昨天 23:41~08:07 睡觉（正在） → 12:04~12:44 午饭 → 18:33~19:13 晚饭
```

★ **不外部改情绪**：这里只给"你被吵醒了"这个事实，心情变不变由**对话模型自己**调 `emotion_set`
决定 —— 与第八轮"情绪交还给对话模型"的决定一致。

### 3.3 与旧 `quietHours` 的关系

`chatluna-proactive` 与 `chatluna-followup` 现在都会问一句 `ctx.chatluna_routine.isQuiet()`：
睡觉时段**不主动插话、不自动跟进**（被叫到时照常回话，只是不主动）。分工是：

- `quietHours`（01:00-08:00）：**钟点**规则 —— 这个点别出声；
- 作息表：**状态**规则 —— bot 现在在睡觉，而且这件事它自己知道、记忆里也有。

两者不冲突，谁命中都闭嘴；只配一个也能用。

### 5.2 对话模型自己改正了图片描述（用户要测的那件事，第一天就发生了）

04:13 群友引用一张图说「**这张图是你自己哦**」，7 秒后模型调了 `vision_correct`：

| | 内容 |
|---|---|
| 改前 | `蓝发猫耳女仆睁大眼睛，旁边写着"!!?"。` |
| 改后 | `[可能自己] 蓝色长发、蓝眼的女仆装少女，头上是两只尖耳朵（**被画成了猫耳，其实本鱼是鲸鱼鳍形状的耳朵**），戴白色蕾丝发箍，睁大眼睛、一脸震惊，旁边写着"!!?"` |
| 库里记的 | `correctedBy: tool:vision_correct`｜`correctedAt: 04:13:49`｜`selfFlag: maybe` |

它在群里的回话是：「诶？那是猫耳吧……我可是鲸鱼鳍🐋 凌晨四点把我叫来就为了说这个？（其实还挺好看的……）」
—— 既认了这是自己（所以才有"我可是…"），又对"猫耳"这个画法提了意见，还顺手抱怨了被吵醒。

**这条记录正好把三件事串起来**：视觉描述可被模型自己修正（`vision_correct`）、修正在库里留痕
（`correctedFrom/correctedBy/selfFlag` 三列）、而 `/look` 就是专门用来看这三件事的。

★ 顺带说明**为什么当天的新图没有自动带标记**：那张图是**老缓存命中**（`027fcd8392b6929e`），
描述是几天前解析的、当时还没有自我识别。**缓存命中不会重解析**，所以：

- 想让它以后"重新认一遍"所有老图 → 把 `chatluna-vision` 的 `CACHE_VERSION` +1（旧行自动失效重解析）；
- 只想修某几张 → 用 `/look` 找到它、`/vision.correct <hash前缀> <新描述>`（或在群里纠正让它自己调工具）。
