# R4 好感度（现成插件 + 自写桥）

> 属于 [QQ 机器人项目 —— 进度与交接](../进度与交接.md) 的分册。
> 旧编号（如「第八·十三节」）的去向见索引页的章节对照表。

`chatluna-affinity` 0.3.15 + 自写「好感度 → 2 级信任」桥。

### 需求原文

> 「与不同群成员的关系度/好感度区分」——bot 得对每个人有**不同的态度**，
> 而且这个态度要能被记录、被累积、被读出来。

### 产物

| 件 | 说明 |

### ★ 四条硬事实（都踩过）

1. **提示词变量名只能是 ASCII。**
   `@chatluna/shared-prompt-renderer` 的标识符规则是
   `[a-zA-Z_$][a-zA-Z0-9_$]*`（`lib/index.cjs:736-741`），中文名**解析不了**。
   把 `affinityVariableName` 配成 `好感度` 时，插件照样打印
   `好感度变量已注册: 好感度`，但预设里写 `{好感度()}` **会原样留在系统提示词里**
   （实测：提示词里就是字面量 `{好感度()}`）。→ 用默认的 `affinity`。
2. **变量必须带 scopeId 参数。** `{affinity()}` 返回**空串**（源码里
   `const scopeId = resolved?.scopeId; if (!scopeId) return ""`），
   必须写 `{affinity("affinity")}`（2026-10-04 之前写的是 `"xingyuan"`）。
   这个坑很阴：不报错、不警告，只是那一段变成空的。
3. **好感度数值不会自己涨。** 真正改数值的只有三条路：模型调 `affinity_affinity` /
   XML 动作 / `/adjust`（全项目 `applyAffinityDelta` 只有 3 个调用点）。
   所以**预设里必须明确教它什么时候调** —— 2026-10-04 那版把措辞从
   「别频繁调」改成「每次开口前对一次账：有变化就调一次，真的毫无变化才不调」，
   因为实测旧措辞下模型**一天 0 次调用**，排行榜数值永远冻着。
   ★ 2026-10-04 晚复测：模型**确实在调**（sandbox 留档 `chatluna-sandbox.model-request` 里能捞出
   完整的 `affinity_affinity` 调用 + `已调整 …：+2` 返回），所谓"改不了"是**下一条**造成的。
4. **`chatCount` / `lastInteractionAt` 曾经完全不更新**（2026-10-04 修）：
   那条「每轮回复后记账」的通道被 affinity 挂在 `chatluna_character.getTemp` 上，
   而社区版 ChatLuna **没有这个服务**（`inject.optional` 所以不报错，静默死掉）。
   现在由自研的 [chatluna-affinity-bridge](../koishi-app/external/koishi-plugin-chatluna-affinity-bridge/lib/index.js)
   提供垫片补上 —— 详见 [坑 61](04-踩坑记录.md) 与 [坑 62](04-踩坑记录.md)。
   **它一旦生效，「新用户自动建档」也跟着复活**：修复前 `/rank` 永远只有最早那两行。
5. **短期/长期两层**：变化先进 `shortTermAffinity`，累计到 `promoteThreshold`(默认 15)
   才按 `longTermPromoteStep`(默认 3) 折进长期；短期跌到 `demoteThreshold`(默认 -10)
   才从长期扣 `longTermDemoteStep`(默认 5)；显示值 `affinity` = `round(长期 × 系数)`。
   实测主人两次「加好感」= 短期 10、长期仍是 30（还没到 15）。
   → 这就是「bot 改不了好感度」的真凶：模型连调 4 次短期 +10，`/rank` 上**一个字都没变**，
   看起来像工具失灵。
   ★ 2026-10-04 晚试过 `affinityDynamics.disableShortTermAffinity: true`（让 delta 直接改长期），
   **用户当天要求撤回**，配置已还原成插件默认 —— 保留两层，改用下面这条**只读**命令把它看穿。
   ★ **系数还开着**：显示值仍是 `round(长期 × 系数)`，系数在 ±0.3 内飘（同一天正向互动 +0.05、
   隔天不互动或负向 -0.05/天）—— 所以长期 30 可能显示 29 或 32，**这也不是 bug**。

### `/short`：把「短期」那层摊开看（只读命令，2026-10-04 晚加）

为什么加它：显示值只看长期 × 系数，短期是**看不见的中间层** —— 模型调了工具、日志也写了
`已调整 …：+2`，但 `/rank` 上纹丝不动，看起来就像"bot 改不了好感度"。
原插件的 `/favor`(`affinity.inspect`) 一次只看**一个人**、且混在一堆字段里；
这条命令一眼看**所有人各攒了多少、距折算/降级还差几点**。

| 件 | 说明 |
|---|---|
| 落在哪 | **自研 [chatluna-affinity-bridge](../koishi-app/external/koishi-plugin-chatluna-affinity-bridge/lib/index.js)** 里（它本来就是"好感度这边我们自己那块"），命令名 `affinity.short`，别名 **`/short`** |
| 用法 | `/short`（所有人）　`/short 2791932480`（某人，也吃 `@2791932480` 与 `onebot:2791932480`）　`/short -l 30`（多显示几行） |
| 权限 | `authority: 1`（和 `/rank`、`/favor` 一致）；**只读，绝不写库** |
| 显示的名字 | **`名字（QQ）`**，名字现场跟平台要：① `bot.getGuildMemberList(guildId)` 一次拿全；② 列表没覆盖到的，逐个走 OneBot `getGroupMemberInfo` / Satori `getGuildMember`。字段优先级照抄 affinity（`card` 群名片 > `remark` > `displayName` > `nick` > `nickname` > `name` > `user.*`），保证 `/short` 与 `/rank` 对同一个人显示同一个名字。**取不到名字时只打 QQ 一次**（绝不 `QQ（QQ）`） |
| 配置 | `shortCommand`(默认 true)、`affinityScopeId`(默认 `affinity`，★必须和 affinity 的 scopeId 一致)、`shortLimit`(20)、`promoteThreshold/demoteThreshold/promoteStep/demoteStep`(**仅用于显示**，要和 affinity 那边配的值一致) |

输出长这样（2026-10-04 23:0x 的真实生产数据）：

```
【短期好感度】scopeId=affinity ｜ 折算线 +15（→ 长期 +3） / ≤-10（→ 长期 -5）
9 人有档案（有短期存量的排前面）：
1. 绮罗星([ゝω・)☆（3669413177）　短期 +10 ｜ 再 +5 折算成长期 +3 ｜ 长期 30 ｜ 显示 30 ｜ 聊过 13 次
2. 小鱼干（2969981414）　短期 +6 ｜ 再 +9 折算成长期 +3 ｜ 长期 30 ｜ 显示 30 ｜ 聊过 17 次
…
8. 1513371097　短期 -2 ｜ 再 -8 降级（长期 -5） ｜ 长期 30 ｜ 显示 29 ｜ 聊过 6 次   ← 拿不到名字就只打 QQ
★ 短期不参与显示值：显示值 = 长期 × 系数（系数在 ±0.3 内随互动/冷淡浮动，所以长期 30 可能显示 29~32）。
```

★ **三个实测出来的技术坑**：

1. **`ctx.database.get('chatluna_affinity_v2', …)` 依赖"表已被声明"。** minato 的
   `getDriver()` 对没声明的表直接 `throw cannot resolve table` —— 本命令能用，是因为
   **chatluna-affinity 自己 `ctx.model.extend('chatluna_affinity_v2', …)`**
   （[它的 lib/index.js:990-1005](../koishi-app/node_modules/koishi-plugin-chatluna-affinity/lib/index.js#L990-L1005)）。
   affinity 没加载时命令会给出人话（"好感度表还没被声明 —— chatluna-affinity 没加载或没起来？"）。
   核对脚本：`.scratch/check-short-minato.cjs`（真 minato + 真 sqlite 驱动，在库副本上跑）。
2. **`lastInteractionAt` 经 minato 回来是 `Date` 对象**（字段类型 `timestamp`），
   而直接读 sqlite 是**毫秒数字** —— 格式化函数两种都得吃，否则会渲染出 `Invalid Date`。
3. **★「显示的全是 QQ 号」的真凶是 `getGuildMemberList` 的返回形状。**
   Satori/koishi 下它回的是 **`{ data: [...] }`**，**不是裸数组**；
   第一版照 `for (const m of list)` 写 → `TypeError: list is not iterable` → 被 try/catch 吃掉 →
   名字表恒为空 → 页面上全是 `3669413177（3669413177）`。
   另外**库里的 `nickname` 列不可当名字**（生产里存的就是 QQ 号本身，affinity 建档时没解析到群名片
   就回落成 userId）—— 名字只能现场跟平台要，`card` 优先。两条都钉在
   `.scratch/check-short-cmd.cjs` 的 J 段与 `.scratch/check-short-command.cjs` 的 E 段
   （后者用假的 `{data:[…]}` 与"只有单查接口"的两种 bot 各验一遍）。

核对（都不碰生产库；后两个把它们自己的库**副本**建在 `.scratch/` 再用完删掉）：

```powershell
node .scratch\check-short-cmd.cjs        # 36 条：纯函数 + 真实生产行（只读）+ 名字解析各种形状
node .scratch\check-short-minato.cjs     # 10 条：真 minato + 真 sqlite 驱动（含"未声明表会 throw"的实证）
node .scratch\check-short-command.cjs    # 17 条：真 koishi 应用里真加载插件、真跑 /short（名字/注册/别名/-l/权限/错误路径）
```

### 自写桥：好感度 → 2 级「信任」

`qqbot-auth` 里新增：

```js
// attach-user 钩子（core:804 是 await ctx.serial(...)，所以能 async）
let want = authorityOf(userId)                 // 名单优先
if (want === null && cfg.affinityScopeId) {
  const cur = session.user.authority ?? 1
  if (cur <= 2) {                              // ★ 3/4 级是人工设的，绝不掀掉
    const aff = await affinityLevel(userId)    // 读 chatluna_affinity_v2，10 秒缓存
    if (aff === 2 && cur < 2) want = 2
    else if (aff === 1 && cur === 2) want = 1
  }
}
```

设计要点：
- **只接管 0/1/2**：`/权限设置` 给的 3、4 级不会被好感度掀掉。
- **滞后带**（51 上 / 40 下）：避免在阈值上反复横跳。
- **10 秒缓存**：`attach-user` 每条消息都跑；一开始写 60 秒，结果「刚调高好感度、
  下一条消息还是旧等级」（实测踩到），改成 10 秒。
- 名单（主人/管理员/信任/拉黑）**永远优先**，好感度只是名单外的默认值来源。

### 为什么没开它的黑名单 / 关系工具

- **黑名单**：R13 已经有 `blockedIds` 名单 + 0 级拦截，再开一套 `chatluna_blacklist_v2`
  会出现「两套拉黑、互相不知道」的状态，排查起来很痛苦。**只留 R13 的那套。**
  （它的黑名单守卫中间件仍在跑，但表是空的，等于 no-op。）
- **关系**：`relationship` 工具给人打「小祥姐姐」这种标签，需要先在配置里铺
  `relationships` 表才有意义；等真需要用再加。

### 调参入口与代价

- 控制台 `/plugins/` → `chatluna-affinity`：`scopeId`、初始好感度（默认 30）、
  短期阈值/长期步长、系数（衰减/加成）、好感度区间→关系映射、变量名、原生工具开关。
- 控制台里还有个**好感度仪表盘**（`enableDashboard`，默认开），能看每天的快照。
- 每条消息会多几次 sqlite 查询（affinity 自己记 chatCount + 我们读一次好感度，10 秒缓存）。
- `/chatluna.tool.list` 现在有 8 个工具 —— 工具越多，每次请求的 token 越多，别再无脑加。

### 踩过的其它坑

- **伪 OneBot 缺 `get_group_member_list`**：`/好感度排行` 会直接回
  `无法获取本群成员列表，暂时无法展示排行。`。已给 `fake-onebot.mjs` 补上
  `get_group_member_list` / `get_group_member_info`（昵称取自剧本里的 `name`），
  顺带 `/好感度详情` 也终于显示昵称而不是 QQ 号。
- 它的指令自带等级：`rank`/`inspect` = 1，`blacklist` = 2，
  `block`/`unblock`/`tempBlock`/`tempUnblock`/`clearAll`/`adjust` = **4**。
  和我们的 R13 分级一致，**没有改动**。
